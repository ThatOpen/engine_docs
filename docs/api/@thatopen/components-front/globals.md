## Enumerations

| Enumeration | Description |
| :------ | :------ |
| [DeferredAoMode](enumerations/DeferredAoMode.md) | Which ambient-occlusion estimator feeds the denoise + composite. SCREEN_SPACE is the Hi-Z Alchemy disk; WORLD_SPACE is the hemisphere-probe estimator with a metre-stable contact footprint. Matches the old DeferredPipeline enum value-for -value so consumers keep working after the swap. |
| [EdgeDetectionPassMode](enumerations/EdgeDetectionPassMode.md) | The mode of the edge detection pass. |
| [GraphicVertexPickerMode](enumerations/GraphicVertexPickerMode.md) | - |
| [HovererMode](enumerations/HovererMode.md) | How the Hoverer reacts to cursor input.  - [HovererMode.MOUSE_STOP](enumerations/HovererMode.md): hover detection runs once the   cursor has settled briefly. Matches the classic "wait for the user   to stop moving" feel: less jittery, useful when hover is paired   with a heavy reaction. - [HovererMode.MOUSE_MOVE](enumerations/HovererMode.md): hover detection runs continuously   as the cursor moves, throttled to one pick per animation frame.   Snappier, ideal now that GPU-readback picking is sub-millisecond. |
| [MeasurementLineType](enumerations/MeasurementLineType.md) | How measurement lines are rendered. - `Basic`: `THREE.Line` with a `LineBasicMaterial`. This is the default and   matches the historical behavior; note WebGL ignores line width here, so   lines always render 1px regardless of `lineWidth`. - `Fat`: `Line2` / `LineSegments2` with a `LineMaterial`, which honors   `lineWidth` (in screen pixels).  Modeled as an enum so more line styles can be added later without a breaking change. |
| [MeasurementPickMode](enumerations/MeasurementPickMode.md) | When the measurement tool runs the snap pick that drives the preview marker / dimension line.  - [MeasurementPickMode.MOUSE_MOVE](enumerations/MeasurementPickMode.md): pick once per animation   frame while the cursor is moving. Snappy feedback; defaults   here. Heavy on big models because every move triggers a pick   (~15 ms GPU readback) plus a snap fetch on first sight of each   new item. - [MeasurementPickMode.MOUSE_STOP](enumerations/MeasurementPickMode.md): pick only after the   cursor settles for Measurement.delay ms. One pick per   stop, regardless of how the user got there. Recommended for   large scenes — the marker only appears where the user actually   pauses, which is also where they're about to click. |
| [PostproductionAspect](enumerations/PostproductionAspect.md) | The postproduction enums live in their own leaf module ON PURPOSE.  They used to be declared in `./index`, which imports the renderer back from `..` — a cycle. Which module evaluates first then depends on the consumer's bundler, and a class field initialized from one of these enums can read it while its module is still half-initialized (`undefined.DEFERRED`, a TypeError at load). A leaf module has no imports, so it can never lose that race. Do not import anything here. |
| [PostproductionMode](enumerations/PostproductionMode.md) | The rendering pipeline the postproduction runs. COMPOSER is the default EffectComposer style stack; DEFERRED is the forward + auxiliary-geometry-prepass pipeline. An enum (rather than a boolean) leaves room for further modes. |

| [NearPlaneLineMaterial](classes/NearPlaneLineMaterial.md) | A fat line material (screen-space quad expansion, real `linewidth` in px) that is also SAFE across the camera near plane.  three's stock `LineMaterial` expands each segment into a screen-space quad in the vertex shader. When a segment endpoint is behind the camera plane its projected `w <= 0`, so the NDC math is garbage and the quad blows up to span the whole screen — the "infinity streak" seen under clipping (and on LOD wires). Stock `LineMaterial` handles only the case where ONE endpoint is behind (it trims that endpoint to the near plane via `trimSegment`); it does nothing when BOTH endpoints are behind, which is the remaining streak.  This subclass injects the missing both-behind guard: if both endpoints are behind the camera plane the segment has no valid projection, so we collapse it offscreen (`gl_Position` past the far plane) instead of expanding a bogus quad. This mirrors the near-plane guard of fragments' LOD line shader: one guard, shared semantics across the fat-line consumers (section edges, measurement lines, LOD wires).  The guard lives in the material's OWN `vertexShader` string (NOT an `onBeforeCompile` patch), so it SURVIVES `.clone()` — `ShaderMaterial.clone` copies `vertexShader`, whereas it drops `onBeforeCompile`. That matters because `ClipEdges` clones the style material per model in local-clipping mode. |

Supports multiple named outline groups so different selections can be outlined with different colors / thicknesses at the same time. 📕 [Tutorial](https://docs.thatopen.com/Tutorials/Components/Front/Outliner). 📘 [API](https://docs.thatopen.com/api/@thatopen/components-front/classes/Outliner). |
| [PointCloudLoader](classes/PointCloudLoader.md) | Loads and streams out-of-core point clouds (Potree 2.0 octrees) and draws them THROUGH the world's deferred [PostproductionRenderer](classes/PostproductionRenderer.md): points stream by LOD and are drawn into the deferred occlusion seam, so they are correctly occluded by BIM geometry with no shader patching. Georeferenced precision (float64 anchor) and the tuned point material (adaptive sizing, overlap, max-size clamp, EDL) are handled internally — the app just points it at an octree.  `potree-core` is an OPTIONAL PEER DEPENDENCY — it is loaded lazily inside [load](classes/PointCloudLoader.md#load), so apps that never load point clouds don't need it installed. |
| [PostproductionRenderer](classes/PostproductionRenderer.md) | A class that extends RendererWith2D and adds post-processing capabilities. 📕 [Tutorial](https://docs.thatopen.com/Tutorials/Components/Front/PostproductionRenderer). 📘 [API](https://docs.thatopen.com/api/@thatopen/components-front/classes/PostproductionRenderer). |
| [RendererWith2D](classes/RendererWith2D.md) | A basic renderer capable of rendering 3D and 2D objects ([Objec3Ds](https://threejs.org/docs/#api/en/core/Object3D) and [CSS2DObjects](https://threejs.org/docs/#examples/en/renderers/CSS2DRenderer) respectively). |
| [SplatLoader](classes/SplatLoader.md) | Streams 3D Gaussian splats THROUGH the world's deferred [PostproductionRenderer](classes/PostproductionRenderer.md) as a first-class citizen of the pipeline.  The splats are drawn by the in-house WebGL2 GSplat renderer (EWA covariance billboards, a worker-driven global depth sort, a 10³ cell grid for distance LOD + frustum culling). They are rendered into the deferred occlusion seam in LAYER mode (premultiplied over the finished frame); critically, every splat writes its CENTRE's reversed-Z depth and the material depth- TESTS (`GreaterEqualDepth`, no depth write) against the BIM depth borrowed by the seam — so BIM geometry occludes the splats with NO shader patching, exactly as a real mesh would.  This replaces the previous Spark + 3d-tiles-renderer implementation; those optional peer dependencies are no longer needed. |
